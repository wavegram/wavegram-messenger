# Мессенджер

Свой мессенджер с нуля: сервер на Node.js, хранение в SQLite, обмен в реальном времени по WebSocket, веб-клиент без сборки и внешних платформ. Личные чаты шифруются в браузере — сервер видит только шифротекст.

## Запуск

```powershell
npm install
npm start
```

Откройте http://localhost:3000 (или адрес в локальной сети, который сервер напечатает при старте).

```powershell
$env:PORT=8080; npm start
```

## Что умеет

**Личные чаты**
- Регистрация и вход по логину и паролю: scrypt с солью, сессии в HttpOnly-куке.
- Сквозное шифрование в браузере: ECDH P-256 → HKDF-SHA256 → AES-GCM 256, свой ключ на каждый чат.
- Отметки о прочтении, непрочитанные, история с подгрузкой по 50, группировка сообщений, ссылки.

**Группы**
- Создание группы, вход по коду приглашения, публичная ссылка `@username`.
- Роли: владелец, администратор, участник. Владелец назначает админов, исключает участников, удаляет чат.
- Администраторы меняют название, описание, публичную ссылку и перевыпускают код приглашения.
- Настройка «история для новых участников»: если выключена, новый участник видит только сообщения после входа.

**Каналы**
- Создание канала, вход по `@username` или коду, счётчик подписчиков.
- Писать могут только администраторы, подписчики читают; композер у подписчика блокируется.
- Те же настройки, что у групп, плюс удаление и выход.

**Интерфейс**
- Меню в стиле Telegram: новая группа, новый канал, присоединение по ссылке, настройки, ночной режим, о приложении, выход.
- Отдельный экран настроек с разделами: профиль, конфиденциальность и безопасность, уведомления, оформление, данные и память, о приложении.
- Смена пароля, активные сеансы с завершением, скрытый статус «в сети», светлая и тёмная темы, звук уведомлений.
- Экран информации о чате: ссылка, участники с ролями, изменение настроек, выход и удаление.

**Защита**
- Проверка прав на каждом запросе, ограничение частоты сообщений и попыток входа, лимиты длины.
- Защита от выхода за пределы каталога статики.

## Как устроено шифрование

1. Браузер создаёт пару ключей ECDH P-256, публичный ключ уходит на сервер, приватный остаётся в `localStorage`.
2. Для личного чата обе стороны выводят общий секрет ECDH → HKDF (`chat:<id>`) → ключ AES-GCM.
3. Текст шифруется AES-GCM со случайным IV и уходит как `e2e1:{"iv":…,"ct":…}`.

**Важно:** группы и каналы, как и в Telegram, не используют сквозное шифрование — сообщения хранятся на сервере и защищены доступом, а не E2E. Сквозное шифрование действует только в личных чатах.

Ограничения E2E: ключ живёт в одном браузере, сверки отпечатков нет, прямой секретности нет, при очистке данных браузера ключ теряется.

## Чего пока нет

Группы и каналы сделаны не полностью «как в Telegram». Не реализовано: закреплённые сообщения, реакции, редактирование и удаление сообщений, пересылка, ответы, упоминания, поиск по чату, темы (topics), медленный режим, обсуждения у каналов, заявки на вступление, срок действия приглашений, тонкие права администраторов (сейчас роль даёт все права), аватары чатов, статистика, монетизация, боты, опросы, медиа и звонки.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/register`, `/api/login`, `/api/logout` | вход и выход |
| GET/PATCH | `/api/me` | профиль: имя, «о себе» |
| POST | `/api/keys` | публичный ключ ECDH |
| POST | `/api/password`, `/api/privacy` | смена пароля, скрытый статус |
| GET/DELETE | `/api/sessions` | активные сеансы |
| GET | `/api/users` | люди со статусом и ключом |
| GET | `/api/chats` | чаты с непрочитанным и ролями |
| POST | `/api/chats` | `{userId}` — личный чат; `{kind, title, …}` — группа или канал |
| PATCH/DELETE | `/api/chats/:id` | настройки или удаление чата |
| GET/POST/DELETE | `/api/chats/:id/members` | участники, роли, исключение |
| POST | `/api/chats/:id/invite` | перевыпуск кода приглашения |
| POST | `/api/chats/:id/leave` | выход из чата |
| POST | `/api/join` | вход по коду или `@username` |
| GET/POST | `/api/chats/:id/messages` | история и отправка |
| POST | `/api/chats/:id/read` | отметка о прочтении |

WebSocket `/ws`: `send`, `typing`, `read` от клиента; `hello`, `message`, `typing`, `presence`, `read`, `chat`, `chats-changed`, `chat-removed` от сервера.

## Проверка

Сквозной тест: 67 проверок, все проходят — вход и сессии, доставка и история, шифрование и ключи, настройки профиля, приватность, смена пароля с завершением сеансов, создание группы и канала, вход по коду и по имени, права на публикацию в канале, смена названия, история для новых, исключение и удаление.

## Безопасность

Сейчас всё работает по HTTP в локальной сети. Для публикации нужен домен и TLS: без него куки сессии и шифротекст идут открытым текстом, а браузерные API шифрования доступны только в защищённом контексте.
